# 第一版需求

## 用户问题

普通用户在使用 Redis 时遇到技术问题，希望获得基于固定版本官方文档、可以追溯来源的排查建议。若自动排查没有解决问题，用户可以授权查询自己的模拟设备，并确认创建技术工单。

## 核心用户流程

1. 用户登录并提出 Redis 技术问题。
2. 系统检索文档，返回带引用回答；无可靠证据时拒答或转人工。
3. 用户反馈未解决后，系统请求查询设备的许可。
4. Java 服务验证登录用户对设备的访问权限，返回脱敏状态。
5. 系统给出后续建议；仍未解决时生成工单草稿。
6. 用户明确确认后，Java 服务使用幂等键创建工单。
7. 用户查看工单状态；客服按合法状态机处理。

## 核心非功能要求

- 引用必须对应真实 chunk，不能由模型生成不存在的来源。
- 模型提出工具请求，Java 服务拥有最终执行权。
- 依赖调用必须设置超时；重试次数有限。
- 所有敏感工具调用需要审计。
- 评测必须使用固定数据集和可复现配置。
