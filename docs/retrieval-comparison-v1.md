# 检索方案首轮对比（50 题）

## 数据与口径

- 评测题：50 条，其中 45 条有证据问题、5 条越界拒答问题。
- 语料：Redis Open Source 7.4 英文官方文档与两篇中文工程实践文档。
- 查询：以中文为主，保留 Redis 命令、配置项等英文专有名词。
- 指标：Recall@1/3/5、MRR、命中题数、平均/P50/P95 检索延迟。
- 拒答题不计入检索 Recall；拒答能力由回答层评测负责。

## 观察

1. **BM25 并不适合当前跨语言设置。** 文档主体是英文，问题主体是中文，词法交集主要来自
   Redis 命令名和配置项，因此 BM25 只命中 3/45。
2. **等权 RRF 不是天然提升。** 低质量 BM25 排名获得与 Dense 相同的投票权，把 Dense
   已召回的正确证据挤出 Top-5，Recall@5 从 0.6222 降至 0.4222。
3. **Reranker 显著改善首位排序。** Recall@1 从 Dense 的 0.3778 提升到 0.5333，MRR 从
   0.4689 提升到 0.5600；但候选召回上限不足使 Recall@5 仍略低于 Dense。
4. **重排有明确延迟代价。** CPU 上平均约 436ms，P95 约 647ms。它是否值得启用应由
   首位命中收益、端到端延迟预算和回答质量共同决定。

## 已发现的代表性失败

Dense 能命中但等权 RRF 丢失的题目包括：MOVED 重定向、Cluster 写安全、小聚合类型紧凑编码、
最少副本写入限制、复制过期机制、ROLE、Sentinel TILT、哈希槽和 ACL 密码存储。这些题说明
融合阶段的问题不是文档缺失，而是候选排序被低质量词法结果干扰。

## 下一轮实验（预注册，避免看结果后随意调参）

保持同一 50 题评测集与索引不变，只调整以下参数：

1. Dense-only 基线；
2. Weighted RRF：Dense/BM25 权重尝试 `2:1`、`4:1`、`8:1`；
3. 候选数 `candidate_k`：20、40；
4. 重排数 `rerank_k`：10、20；
5. 以 Recall@5 为主要指标，MRR 与 P95 延迟为次要指标；
6. 不根据单道题单独增加停用词或特判规则。

只有在加权融合同时满足以下条件时才替换 Dense 基线：Recall@5 不低于 Dense，且 MRR 有稳定提升。
