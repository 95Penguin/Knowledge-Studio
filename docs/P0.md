# P0 必做范围

P0 的目标不是堆功能，而是交付一个有真实文档、固定评测、业务权限和异常处理的完整故障处理闭环。

## P0-0：需求冻结与工程骨架

- [x] Python FastAPI 与 Java Spring Boot 基础目录
- [x] 健康检查接口和基础配置
- [x] 用户流程、范围、工具契约和评测格式初稿
- [x] 确定 Redis 文档版本：Redis Open Source 7.4 官方英文文档（语料快照尚待下载）
- [x] 完成可重复获取脚本、候选主题白名单、排除规则和 Manifest 模板
- [x] 下载语料快照并记录具体 commit、许可证、来源和获取日期
- [ ] 自己检查并解释两个服务的启动链路

验收证据：两个健康检查接口可运行；需求文档不存在互相冲突的规则。

- [x] chunk 可以反向定位到原文和章节

验收证据：解析测试、处理统计、随机抽样 20 个 chunk 的人工检查记录。

## P0 完成定义

以下条件全部满足才算 P0 完成：

1. 使用真实、固定版本文档，不用三五篇自造文本代替；
2. 80～100 条固定评测集可重复运行；
3. 四种检索方案有真实对比结果；
4. 故障处理到创建工单形成完整闭环；
5. Agent 不能绕过 Java 权限与业务规则；
6. 异常和攻击性输入有测试；
7. 别人能按 README 启动并完成演示。

## 暂不属于 P0

- 多 Agent、模型微调、本地部署大模型
- 多租户、复杂 RBAC、长期记忆
- Kubernetes、完整微服务治理
- 大量业务工具和多个文档领域
- 精美前端和移动客户端
